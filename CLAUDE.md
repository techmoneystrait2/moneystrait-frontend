# Moneystrait frontend

The website at `moneystrait.com` for Halvern LLC, trading as Moneystrait. It gets registered businesses to book a call. Every page leads to "Get your rate"; "Chat with us" is second. The backend is a separate repo, reached only through `/api/*`. This file stands alone.

## Stack

Next.js with TypeScript. Marketing pages are static, rebuilt when the CMS publishes, and served from the CDN. CMS: Sanity, Payload or Strapi (not chosen). Analytics: Plausible by default. Bot protection: invisible Cloudflare Turnstile. Keep vendors behind interfaces.

## Commands

Copy `.env.example` to `.env.local` first. `/api/*` is forwarded to `BACKEND_URL`. `AGENTS.md` is generated by `next dev`; commit it.

```bash
npm run dev
npm run build
npm start
npm run lint
```

## Hard rules (also in the backend repo; change both)

- No public prices: no Moneystrait price, rate, fee, margin, range or saving figure in pages, metadata, structured data, ad landing pages or emails. Rates appear only in the rate letter, sent to approved companies.
- Registered businesses only, funded only from their own bank accounts or verified wallets. They can pay companies or people. Never offer "get paid", payment links, invoicing or collecting from third parties.
- Name a regulator only while its licence row is published and its evidence is on file. Never "licensed in [country]". FinCEN and FINTRAC are registrations: never call them licences.
- Name MiCA only with a MiCA CASP authorisation. USDT is not offered to EU or EEA companies.
- Restricted at launch: Cuba, Iran, North Korea, and the Crimea, Donetsk and Luhansk regions of Ukraine. The list lives in the CMS and is never hard-coded.
- Messages about checks stay neutral. A refused application never gets a reason.
- No ID images, company documents or ID numbers on our side; Sumsub keeps them. No personal data in logs or analytics.
- Nothing goes live with a [bracket] placeholder. Sample names and amounts are never presented as real.
- Never hard-code anything private: keys, tokens, passwords, connection strings, signing secrets or webhook secrets. Not in code, tests, docs, comments, logs or fixtures. Read them from environment variables.
- Local values live in an untracked `.env`; production values live in the host's secret store. Commit only `.env.example`, with blank values, and add every new variable to it in the same change.
- If a secret is ever committed, rotate it at once; deleting it from the code is not enough.
- Add no CI, GitHub Actions, Docker or other DevOps files. The owner deploys the frontend to Vercel and the backend to Render.

Anything prefixed `NEXT_PUBLIC_` ships to every browser, so use that prefix only for values meant to be public, such as the Turnstile site key. Secrets belong in the backend repo; this repo holds only the CMS read token, on the server side.

## Banned words (must not appear on the site)

| Don't write | Write instead |
|---|---|
| instant, instantly | "Minutes", "Same day" from country data |
| guaranteed, risk-free, as safe as a bank | "Every payment screened" |
| no KYC, no questions asked | "One check when you join" |
| P2P | "unregistered sellers" |
| send money anywhere | "150+ countries" |
| business accounts only | "For registered businesses" · "Pay companies or people" |
| stablecoins (in menus and buttons) | "Crypto"; name the coins in the text |
| licensed in [country] | "Registered with FinCEN", "Licensed by VARA" |
| get paid, receive payments, payment links, invoices | "Add money from your company's own bank account" |
| cheapest, best rate, lowest fees, any price | "Your own rate, lower than you pay today" |

Owner-approved exception: "invoices" is banned only as something we offer. Copy saying customers don't need invoices stays: "No invoices needed", "No invoices after that", "Do I need an invoice for each payment?".

Two clashes in the brief's copy are still open, so the site uses the safe wording until the owner decides: "UAEFTS, or Aani" and "Move money between them in a few clicks."

Details are on our Licences page. Accounts are held with our partner banks. Accounts are for registered businesses, funded only from their own bank accounts or wallets, and can pay companies or people. Services are not available in every jurisdiction. Moneystrait is not a bank and not a stablecoin issuer. Crypto assets are not bank deposits and are not covered by deposit insurance; they can lose some or all of their value and can be extremely volatile.

"Licences" links to `/licences`. The list of bodies in the second sentence is generated from published licence rows. The small form footer is one line: "© 2026 Halvern LLC. Moneystrait is not a bank." plus Privacy · Terms · Security · Licences.

## CMS-driven licences

- Hard-code no regulator names anywhere. Licence numbers appear only on `/licences`. Until a CMS exists, `content/licences.ts` holds the records; a row stays `published: false` until its number and evidence are real. Anything without a backend or real data shows "currently unavailable".
- Each licence is a CMS record with a published switch: body, what it covers, number, held by, register name and address, published, last checked, evidence (internal only, never rendered).
- Unpublishing removes that body at once from the trust strip, Security card, "Are you licensed?" answer, Crypto comparison and footer sentence.
- Copy, questions, countries, coins, contacts, managers and the 150+ and 200+ figures also come from the CMS, with no deploy. The Crypto risk line is locked: "Crypto can lose some or all of its value and its price can swing sharply. It is not a bank deposit."

## Acceptance

Match the designs at 1440, 1024, 768 and 390 px, with no sideways scroll from 320 px. Lighthouse 90+ on Home, Payments and Talk to us (mobile). WCAG 2.2 AA with no serious axe issues. LCP < 2.5 s, INP < 200 ms, CLS < 0.1. JavaScript at most 150 KB on marketing pages, 250 KB on the form page. Build product pictures in HTML, CSS or SVG, never screenshots. Search must work without JavaScript. Never send personal data to analytics.
